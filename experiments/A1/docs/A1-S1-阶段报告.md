# A1 S1 阶段报告：one-to-one 免 NMS 的 pipeline 打通与首轮消融数字

> 课题：A1｜MoE × End-to-End：现有 one-to-one 能否真正免 NMS
> 阶段：S1（2026-08-25 ~ 09-01）｜作者：delei-kong｜状态：阶段报告（非终版）

## 结论摘要（TL;DR）

1. **四环节 pipeline 已完全打通**：训练 → 推理 → 导出 → 评测，在 A/C 两格全部跑通且数字可复现；每一环节都有独立的可复现验证脚本与证据（详见 §3）。
2. **首轮消融数字已出**（batch=8 统一口径，100 epochs，coco val2017）：

| | NMS on | NMS off（免 NMS） | 免 NMS 相对损失 |
|---|---|---|---|
| **MoE off** | A：mAP50-95 **0.0317** | C：mAP50-95 **0.0197** | **-37.9%** |
| **MoE on** | B：mAP50-95 **0.0260** | D：mAP50-95 **0.0173** | **-33.5%** |

3. **核心发现**：免 NMS 有明确 mAP 代价（约 -33% ~ -38% 相对），且代价在 MoE on/off 两个条件下均存在；**"免 NMS 是否划算"尚不能定论**——交易的另一半（延迟收益）是本阶段的既定后续工作。
4. **意外发现（副产品）**：MoE 在当前 4k 小数据口径下**未见收益**（A→B -18.0%、C→D -12.2%）——可能与 MoE 收敛更慢、数据规模不足有关，需更大数据验证，暂不下结论。
5. **工程资产**：修复了上游 Ultralytics 的 ONNX 导出坐标错位 bug；搭建了多机训练调度体系（任务书 + 检查清单 + 归档脚本），已在 4 台机器上实战验证。
6. **下阶段**：延迟 benchmark（补齐"交易"另一边）→ 路由/模块诊断 → 完整 COCO 复验 → 深化 MoE 分析。

## 2. 实验设计与口径

### 2.1 消融设计（2×2 矩阵）

课题核心问题拆解为两个独立变量的消融：

| 变量 | 取值 | 回答的问题 |
|---|---|---|
| 推理范式 | NMS on（传统 o2m）/ NMS off（one2one 免 NMS） | 免 NMS 的 mAP 代价 |
| 骨干结构 | MoE off（dense yolo26）/ MoE on（A2C2fMoE ×3） | MoE 的收益及其与免 NMS 的交互 |

| 格 | 配置 | model YAML | 结果（mAP50-95） |
|---|---|---|---|
| A | MoE off + NMS on | `yolo26-end2end-false.yaml` | 0.0317 |
| B | MoE on + NMS on | `yolo26-master-end2end-false.yaml` | 0.0260 |
| C | MoE off + NMS off | `yolo26.yaml` | 0.0197 |
| D | MoE on + NMS off | `yolo26-master-n.yaml` | 0.0173 |

**变量控制**：四格仅 `model` 参数不同，其余逐字一致（seed=0、epochs=100、imgsz=640、batch=8、save_period=10）。A/B 与 C/D 的配置差异分别只经 `end2end` 一行 diff 验证（防配置漂移）。

> ⚠️ 数据说明：用 val2017 训练非官方标准口径（val 本该只做评测），绝对 mAP 偏低属预期；**本报告的结论均基于 A/C、B/D 的相对差值**，绝对数字仅作参考。S2 将用完整 COCO train2017（118k 图）复验。

## 5. 分析

**四格 P/R 全景**（最佳 epoch）：

| 格 | 配置 | P | R | mAP50 | mAP50-95 |
|---|---|---|---|---|---|
| A | MoE off + NMS | 0.408 | **0.087** | 0.0631 | 0.0317 |
| B | MoE on + NMS | 0.442 | 0.068 | 0.0513 | 0.0260 |
| C | MoE off + 免 NMS | 0.458 | 0.048 | 0.0400 | 0.0197 |
| D | MoE on + 免 NMS | **0.482** | **0.041** | 0.0346 | 0.0173 |

**分析点 1：免 NMS 的代价是"漏检"，不是"定位不准"**

- A→C：R 0.087→0.048（**-44%**），P 0.408→0.458（**+12%**）
- 免 NMS 的 mAP 损失全部来自漏检（recall 下降），定位质量反而上升（precision 提高）——出的框更准，但大量真实目标未被检出

**分析点 2：MoE 在当前口径下的表现**

- A→B：R 0.087→0.068（-21%），P 0.408→0.442（+8%）；免 NMS 条件下（C→D）同方向：R 0.048→0.041，P 0.458→0.482
- MoE on 在两个推理范式下 mAP 均低于 MoE off（-18.0% / -12.2%），损失结构同样是漏检主导；cls loss 终值更高（B 3.37 > A 3.25；D 3.92 > C 3.80）


### pipeline 成熟度评估

四环节均有验证脚本 + 证据链（args.yaml/results.csv/归档 README/wandb），**数字可复现**（任务书锁定 SHA + 数据拆分清单锁定 seed，任何机器可按任务书重跑）。多机调度体系经 4 机实战验证，任务书-检查清单-归档闭环可用。
