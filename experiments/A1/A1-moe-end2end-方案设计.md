# A1：MoE × End-to-End —— 现有 one-to-one 能否真正免 NMS

## 1. 课题规划

### 1.1 目标与范围
- P0 保底：固定代码版本复现 detect 基线与 end-to-end 路径；记录 mAP50-95、GPU/CPU batch=1 延迟及标准差。
- P1 预期：补齐可训练、可评测、可导出的免 NMS 闭环；2×2 消融（mAP 掉点 ≤2 + CPU 延迟可测改善）。
- P2 理想：扩展到 seg/pose，或有证据的负结果（梯度稀疏、匹配冲突、路由坍塌等机制分析）。
- 交付物清单：闭环修复 PR；2×2 消融表；≥3 seed 或单 seed 局限声明；延迟测试脚本；结项报告。

### 1.2 核心问题拆解
- **Q1 闭环**：one-to-one 路径在训练→推理→导出→评测四环节是否真正无 NMS？各环节口径是否一致？
- **Q2 冲突**：稀疏 MoE 路由与一对一监督是否冲突（收敛、精度、匹配质量、路由行为）？
- **Q3 机制**：若冲突，机制是什么（梯度稀疏 / 匹配冲突 / 路由坍塌）；不冲突同样是有效结论。

### 1.3 主线实验设计（2×2）

| | MoE off（yolo26.yaml） | MoE on（yolo26-master-n.yaml） |
|---|---|---|
| **NMS on**（end2end=False） | A 基线 | B |
| **NMS off**（end2end=True） | C | **D 核心格** |

成功判据：D vs A 的 mAP50-95 掉点 ≤2 且 CPU batch=1 延迟可测改善。

## 2. 模块拆分

**拆分原则**：每个模块有明确的入口代码、交付物、验收标准、依赖关系；不预设人员归属。

| 模块 | 职责 | 入口代码 | 交付物 | 依赖 |
|------|------|----------|--------|------|
| M1 训练闭环 | end2end 训练/验证跑通；o2m/o2o 损失正确性验证；四格训练任务编排 | `loss.py:1186-1231`、`head.py:157-171`、`trainer.py:1550`、`cfg/models/26/*.yaml` | 四格训练 config + 日志 + best.pt | — |
| M2 推理与延迟评测 | 免 NMS 推理链路验证；GPU/CPU batch=1 延迟基准（≥3 次重复 ±std）；postprocess 同口径对比 | `predict.py:33-63`、`nms.py:66` | 延迟脚本 + 基准报告 | M1 首格模型 |
| M3 导出链路 | ONNX/静态量化对 end2end 输出的验证；已知限制边界确认 | `exporter.py:663-672` | 导出矩阵（格式 × end2end）+ 局限声明 | M1 |
| M4 MoE 机制分析 | expert 使用率/Gini、梯度稀疏、匹配冲突、路由坍塌诊断（P2） | `moe/routers.py`、`moe/analysis.py`、`moe/diagnostics.py`；Issue #52 既有证据 | 路由诊断报告 + 机制结论（含负结果） | M1 训练 trace |
| M5 集成与文档 | PR、单测、报告、复现包冻结 | — | 最终 PR；结项报告；复现包 | M1–M4 |

- 依赖图：M1 → {M2, M3, M4} → M5；M2/M3/M4 相互独立可并行。
- 单人串行顺序：M1 → M2 → M3 → M4（M5 滚动进行）。
- 多人认领建议：训练侧（M1+M4）与推理导出侧（M2+M3）天然成两条并行线；M5 共同承担。

## 4. 风险与降级

| 风险 | 触发条件/监测 | 降级动作 |
|------|---------------|----------|
| R1 一对一训练不收敛 | S1 中 A/C 两格 loss 曲线与 mAP 对比异常 | 课题卡降级：one-to-many 主分支 + one-to-one 辅助；结论按负结果呈现 |
| R2 算力不足 | W1 训练时长超出预期 | 缩数据不缩变量（COCO-mini）；不降低 2×2 变量数 |
| R3 导出格式不支持 end2end | M3 验证（已知：exporter.py 对部分格式自动禁用 end2end；静态量化坍缩类别索引） | 限定导出格式范围（如 ONNX FP32），其余格式记为已知局限 |
| R4 延迟口径不一致 | M2 基准复测波动 | 统一脚本：warmup + ≥3 次重复取均值±std；NMS on/off 同口径分列 postprocess |
| R5 路由坍塌/强制均衡 | M4 诊断（Issue #52 已知 balance_loss=1.0 强制均衡） | 作为 P2 机制结论输出（负结果也算产出） |
| R6 成员投入变动 | 任一阶段进度滞后 | 按单人串行顺序兜底（M1 → M2 → M3 → M4），关键路径只保 M1 |
