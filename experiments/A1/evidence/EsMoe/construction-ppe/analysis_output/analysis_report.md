![逐类分析](03_per_class_analysis.png)

### 核心发现

- **强势类别**（AP50-95 >= 0.30）: helmet、gloves、vest、boots、Person —— 共 5 类
- **弱势类别**（AP50-95 < 0.15）: none、no_helmet、no_goggle、no_gloves、no_boots —— 共 5 类
- **no_goggle 和 no_boots** 的 F1 分数为 0，召回率为 0 —— 模型完全无法检测这两个类别

### 易混淆类别对分析

数据集中存在 4 对"有/无"互斥类别：

| 类别对 | 正向 AP50-95 | 负向 AP50-95 | 差异 |
|--------|-------------|-------------|------|
| helmet vs no_helmet | 0.4776 | 0.0565 | 8.5x |
| goggles vs no_goggle | 0.2686 | 0.0291 | 9.2x |
| gloves vs no_gloves | 0.3397 | 0.0168 | 20.2x |
| boots vs no_boots | 0.3587 | 0.0024 | 149x |

**分析**：`no_X` 类别（未佩戴某 PPE）本质上比 `has_X`（佩戴某 PPE）更难检测。因为在视觉上，模型需要"确认某物不存在"而非"确认某物存在"，这是一个更难的表征学习问题。当前模型几乎完全无法区分 `no_X` 类别，倾向于将所有检测归类为 `has_X` 或直接漏检。

**Person 类别表现优异**（AP50=0.82），因为人是大尺寸、特征清晰的目标，这与目标检测的一般规律一致。

## 6. 结论与建议

### 主要发现

1. **v0.1-N 和 EsMoE-N 性能接近**，EsMoE-N 以更少的参数达到了相当甚至略优的效果，性价比更高
2. **no_X 类别是核心瓶颈**：5 个弱势类别中 4 个是 `no_X`，其中 `no_goggle` 和 `no_boots` 完全无法检测
3. **精确率—召回率失衡**：精确率 ~0.79 但召回率 ~0.44，模型偏保守
4. **密集小目标场景表现差**：goggles、gloves 等在多人场景中容易被忽略
5. **训练曲线在 epoch 100+ 后基本持平**，继续增加 epochs 的收益有限

### 改进建议

1. **类别设计重新思考**：`no_X` 类别的实用价值值得商榷。如果实际应用中只需要知道"谁没戴安全帽"，可以通过 `Person` 检测 + `helmet` 检测的差集来实现，无需独立训练 `no_helmet` 类别。去掉 `no_X` 类别可大幅简化任务
2. **针对性数据增强**：对 goggles、gloves 等小目标增加 mosaic + 复制粘贴增强
3. **损失函数加权**：对弱势类别增加分类损失权重
4. **后处理修正**：利用 has_X / no_X 的互斥关系进行后处理融合
5. **MoE 稳定性修复**：final_eval 阶段的 Router NaN 问题需要在代码层面排查，可能与 small dataset + EfficientSpatialRouter 有关
6. **提升召回率**：当前 conf=0.25 阈值下召回率仅 0.44，可适当降低阈值或用 soft-NMS
